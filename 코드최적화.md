3. **DOM 작업 최소화**

### 🎯 최적화 접근법

```
측정 → 병목 파악 → 최적화 적용 → 재측정 → 검증
```

> ⚠️ **주의**: 측정 없이 최적화하지 말 것. 과도한 최적화는 코드 복잡도만 증가시킵니다.

## 주석 스타일 가이드

코드 가독성과 유지보수성을 위해 두 가지 주석 스타일을 사용합니다.

### 📌 스타일 1: 기능 블록 주석 (필수)

**목적:** 비슷한 역할의 코드들을 묶어서 **카테고리**로 구분합니다.

```tsx
// ============================================================
// 1. 기본 훅 설정
// ============================================================
const navigate = useNavigate();
const location = useLocation();
const dispatch = useAppDispatch();
const editorRef = useRef<EditorRef>(null);
```

**사용 시점 & 기능별 분류 예시:**

1. **`1. 기본 훅 설정`** - React 기본 훅들 (navigate, location, dispatch, ref)
2. **`2. 상태 & 데이터`** - Redux 상태, useState, location.state 데이터
3. **`3. 계산된 값 (useMemo)`** - useMemo로 메모이제이션된 파생 데이터
4. **`4. React Hook Form 초기화`** - useForm 설정 및 폼 관련 코드
5. **`5. 유효성 검사 함수`** - 검증 로직 함수들
6. **`6. 이펙트`** - useEffect 훅들
7. **`7. 이벤트 핸들러 (useCallback)`** - useCallback으로 감싼 핸들러들
8. **`8. 렌더링`** - return 문과 JSX

**형식:**

- 구분선: `=` 60개 (시각적으로 명확한 구분)
- 번호와 제목: `// 숫자. 카테고리명` 형식
- 제목: **역할 기반**으로 간결하게 (예: "기본 훅 설정", "상태 & 데이터")
- 총 3줄로 구성

**기능별 묶는 규칙:**

- **같은 Hook 종류**: useState끼리, useMemo끼리, useCallback끼리
- **같은 역할**: 데이터 조회, 이벤트 처리, 유효성 검사 등
- **실행 순서**: 초기화 → 데이터 → 계산 → 효과 → 핸들러 → 렌더링

### 💬 스타일 2: 인라인 설명 주석 (선택)

**목적:** 특정 코드 라인의 **의도나 동작**을 짧게 설명합니다.

#### 2-1. 그룹 내 설명 주석

여러 관련 코드 위에 배치하여 그룹의 목적을 설명합니다.

```tsx
// ============================================================
// 2. 상태 & 데이터
// ============================================================
const userId = useAppSelector((state) => state.auth.Login.data?.data);
const detailData = useAppSelector((state) => state.post.detail.data);

// location.state에서 mode와 데이터 가져오기
const mode = location.state?.mode || "create";
const replyData = location.state?.replyData;
const stateDetailData = location.state?.detailData;

// 선택된 파일들을 추적하기 위한 state
const [selectedFiles, setSelectedFiles] = useState<{
  [key: string]: File | null;
}>({});
// 삭제할 파일 ID들을 추적 (수정 모드에서만 사용)
const [deleteFileIds, setDeleteFileIds] = useState<number[]>([]);
```

**사용 예시:**

- `// location.state에서 mode와 데이터 가져오기` - 관련된 3개 변수 그룹 설명
- `// 선택된 파일들을 추적하기 위한 state` - 단일 state의 목적 설명
- `// 삭제할 파일 ID들을 추적 (수정 모드에서만 사용)` - 목적 + 사용 조건

#### 2-2. 상세 로직 설명 주석

복잡한 로직 내부에서 조건이나 이유를 설명합니다.

```tsx
// ============================================================
// 3. 계산된 값 (useMemo)
// ============================================================
const workerId = useMemo(
  () => userId?.userId || "unknown_id",
  [userId?.userId]
);

// 원글 데이터: state로 전달받은 데이터 우선, 없으면 detailData 사용
const detailDetailData = useMemo(
  () => stateDetailData || detailData?.data?.detail,
  [stateDetailData, detailData?.data?.detail]
);

// URL에서 recKey 추출
const recKey = useMemo(() => {
  const pathRecKey = location.pathname.split("/").pop();
  return initialRecKey || (pathRecKey ? parseInt(pathRecKey, 10) : null);
}, [initialRecKey, location.pathname]);
```

**사용 예시:**

- `// 원글 데이터: state로 전달받은 데이터 우선, 없으면 detailData 사용` - 우선순위 로직 설명
- `// URL에서 recKey 추출` - 복잡한 계산의 목적 명시

#### 2-3. 인라인 값 설명 주석

코드 끝에 배치하여 값의 의미를 추가 설명합니다.

```tsx
const mode = location.state?.mode || "create"; // "create" | "edit"
const replyData = location.state?.replyData; // 수정 모드일 때 답변 데이터
const stateDetailData = location.state?.detailData; // state로 전달받은 원글 데이터

const maxSizeInBytes = 10 * 1024 * 1024; // 10MB
```

**사용 예시:**

- `// "create" | "edit"` - 가능한 값 타입 명시
- `// 수정 모드일 때 답변 데이터` - 사용 시점/조건 설명
- `// 10MB` - 숫자의 의미 명확화

#### 2-4. 조건문 내부 주석

조건 분기 내에서 각 경우의 의도를 설명합니다.

```tsx
const [initialRecKey] = useState<number | null>(() => {
  // 수정 모드일 때
  if (mode === "edit" && replyData) {
    return replyData.parentRecKey || replyData.recKey;
  }
  return location.state?.recKey || null;
});
```

**사용 예시:**

- `// 수정 모드일 때` - 조건의 의미 명확화

### ✅ 주석 작성 원칙

1. **기능 블록 주석은 필수**, 인라인 설명은 필요시에만
2. **번호는 일관성 유지** (1, 2, 3... 순차적, 컴포넌트 전체에서 중복 없이)
3. **주석이 코드보다 길어지지 않도록** 간결하게
4. **"왜"에 집중**, "무엇"은 코드로 표현
5. **업데이트 필수**: 코드 변경 시 주석도 함께 수정
6. **계층 구조 유지**: 대분류(블록) → 중분류(그룹) → 소분류(개별) 순서

---

### 🎯 인라인 주석 사용 기준

| 상황               | 주석 위치       | 예시                                                      |
| ------------------ | --------------- | --------------------------------------------------------- |
| **여러 변수 그룹** | 그룹 위         | `// location.state에서 mode와 데이터 가져오기`            |
| **단일 변수 목적** | 변수 위 또는 끝 | `// 선택된 파일들을 추적하기 위한 state`                  |
| **복잡한 로직**    | 코드 위         | `// 원글 데이터: state로 전달받은 데이터 우선, 없으면...` |
| **타입/값 범위**   | 코드 끝         | `const mode = ... // "create" \| "edit"`                  |
| **조건 설명**      | 조건문 내부     | `// 수정 모드일 때`                                       |
| **매직 넘버**      | 값 끝           | `10 * 1024 * 1024; // 10MB`                               |

### 📝 실전 주석 예제 (ContentReply 기반)

```tsx
export const ContentReply = () => {
  // ============================================================
  // 1. 기본 훅 설정
  // ============================================================
  const navigate = useNavigate();
  const location = useLocation();
  const dispatch = useAppDispatch();
  const editorRef = useRef<EditorRef>(null);

  // ============================================================
  // 2. 상태 & 데이터
  // ============================================================
  const userId = useAppSelector((state) => state.auth.Login.data?.data);
  const detailData = useAppSelector((state) => state.post.detail.data);

  // location.state에서 mode와 데이터 가져오기
  const mode = location.state?.mode || "create"; // "create" | "edit"
  const replyData = location.state?.replyData; // 수정 모드일 때 답변 데이터
  const stateDetailData = location.state?.detailData; // state로 전달받은 원글 데이터

  // 선택된 파일들을 추적하기 위한 state
  const [selectedFiles, setSelectedFiles] = useState<{
    [key: string]: File | null;
  }>({});
  // 삭제할 파일 ID들을 추적 (수정 모드에서만 사용)
  const [deleteFileIds, setDeleteFileIds] = useState<number[]>([]);

  const [initialRecKey] = useState<number | null>(() => {
    // 수정 모드일 때
    if (mode === "edit" && replyData) {
      return replyData.parentRecKey || replyData.recKey;
    }
    return location.state?.recKey || null;
  });

  // ============================================================
  // 3. 계산된 값 (useMemo)
  // ============================================================
  const workerId = useMemo(
    () => userId?.userId || "unknown_id",
    [userId?.userId]
  );
  const name = useMemo(() => userId?.name || "알수없음", [userId?.name]);

  // 원글 데이터: state로 전달받은 데이터 우선, 없으면 detailData 사용
  const detailDetailData = useMemo(
    () => stateDetailData || detailData?.data?.detail,
    [stateDetailData, detailData?.data?.detail]
  );

  // URL에서 recKey 추출
  const recKey = useMemo(() => {
    const pathRecKey = location.pathname.split("/").pop();
    return initialRecKey || (pathRecKey ? parseInt(pathRecKey, 10) : null);
  }, [initialRecKey, location.pathname]);

  // ============================================================
  // 4. React Hook Form 초기화
  // ============================================================
  const {
    register,
    handleSubmit,
    formState: { isSubmitting, errors },
    reset,
  } = useForm({
    defaultValues: {
      boardKey: boardConfig?.recKey || 0,
      parentRecKey: recKey || 0,
      // ...
    },
    mode: "onChange",
  });

  // ============================================================
  // 5. 유효성 검사 함수
  // ============================================================
  // 파일 크기 유효성 검사 함수 (최대 10MB)
  const validateFileSize = useCallback(
    (file: File | undefined): boolean | string => {
      if (!file) return true;

      const maxSizeInBytes = 10 * 1024 * 1024; // 10MB

      if (file.size > maxSizeInBytes) {
        return `파일 크기가 10MB를 초과합니다.`;
      }

      return true;
    },
    []
  );

  // ============================================================
  // 6. 이펙트
  // ============================================================
  // 게시물 데이터 로드
  useEffect(() => {
    if (recKey && !detailDetailData) {
      dispatch(getPostDetail({ recKey }));
    }
  }, [dispatch, recKey, detailDetailData]);

  // ============================================================
  // 7. 이벤트 핸들러 (useCallback)
  // ============================================================
  // 기존 파일 삭제 핸들러 (수정 모드에서만 사용)
  const handleDeleteFile = useCallback((fileRecKey: number) => {
    setDeleteFileIds((prev) => [...prev, fileRecKey]);
  }, []);

  const onSubmit = useCallback(async () => {
    const editorData = editorRef.current?.getData() || "";

    // 에디터 내용 검증
    if (!editorData.trim()) {
      alert("답변 내용을 입력해주세요.");
      return;
    }

    try {
      if (mode === "edit" && replyData) {
        // 수정 모드
        await dispatch(updatePostReply(updateData)).unwrap();
      } else {
        // 생성 모드
        await dispatch(createPostReply(submissionData)).unwrap();
      }
    } catch (error) {
      alert(error);
    }
  }, [mode, replyData /* ... */]);

  // ============================================================
  // 8. 렌더링
  // ============================================================

};
```

## 최적화 기법별 상세 가이드

### 1. 참조 안정화 (Reference Stability)

리렌더를 발생시키는 가장 흔한 원인은 **props 참조 변경**입니다.

#### 1.1 useMemo - 객체/배열 메모이제이션

**언제 사용하나요?**

- 자식 컴포넌트에 객체/배열을 props로 전달할 때
- 파생 데이터를 계산할 때
- 의존성 배열에 넣을 객체를 생성할 때

**적용 전 (❌)**

```tsx
function BoardEdit() {
  const navigationState = {
    mode: location.state?.mode || "create",
    recKey: location.state?.recKey || 0,
    siteCode: location.state?.siteCode || "main",
  };
  // ⚠️ 매 렌더마다 새 객체 생성 → 하위 컴포넌트 불필요한 리렌더

  return <FormSection config={navigationState} />;
}
```

**적용 후 (✅)**

```tsx
function BoardEdit() {
  // ============================================================
  // 1. useMemo로 파생 데이터 메모이제이션
  // ============================================================
  const navigationState = useMemo(() => {
    const state = location.state as {
      mode?: "create" | "edit" | "check";
      recKey?: number;
      siteCode?: SiteCode;
    } | null;

    return {
      mode: state?.mode || "create",
      recKey: state?.recKey || 0,
      siteCode: state?.siteCode || ("main" as SiteCode),
    };
  }, [location.state]);

  return <FormSection config={navigationState} />;
}
```

**효과**

- 자식 컴포넌트 리렌더 70~90% 감소
- 객체 재생성 비용 절감

---

#### 1.2 useCallback - 함수 메모이제이션

**언제 사용하나요?**

- 이벤트 핸들러를 자식 컴포넌트에 전달할 때
- 다른 hook의 의존성 배열에 함수를 넣을 때
- 함수 내부에서 상태를 참조할 때

**적용 전 (❌)**

```tsx
function BoardEdit() {
  const handleListClick = () => {
    navigate(-1);
  };
  // ⚠️ 매 렌더마다 새 함수 생성 → 버튼 컴포넌트 리렌더

  const handleCreate = async (data: FormData) => {
    if (!confirm(`${data.name} 게시판을 생성하시겠습니까?`)) return;
    // ... 로직
  };

  return (
    <>
      <Button onClick={handleListClick}>목록</Button>
      <Button onClick={handleCreate}>생성</Button>
    </>
  );
}
```

**적용 후 (✅)**

```tsx
function BoardEdit() {
  // ============================================================
  // 2. useCallback으로 함수 참조 안정화
  // ============================================================
  // 의존성이 변하지 않으면 동일한 함수 참조 유지
  // 자식 컴포넌트(Button)의 불필요한 리렌더 방지
  const handleListClick = useCallback(() => {
    navigate(-1);
  }, [navigate]);

  const createSubmissionData = useCallback(
    (data: FormData): FormData => ({
      ...data,
      replyYn: "N",
      defaultContent: defaultContentRef.current?.getData() || "",
      privacyContent: privacyRef.current?.getData() || "",
    }),
    []
  );

  const handleCreate = useCallback(
    async (data: FormData) => {
```

**10.2 Selector Context 패턴 (고급)**

```tsx
// ============================================================
// 15. Selector Context로 부분 구독
// ============================================================
// 전체 state가 변해도 필요한 값만 구독
// 불필요한 리렌더 제거
const StoreContext = createContext({
  get: (selector) => selector(state),
  subscribe: (callback) => {},
});

function useSelector(selector) {
  const store = useContext(StoreContext);
  const [value, setValue] = useState(() => store.get(selector));

  useEffect(() => {
    return store.subscribe(() => {
      setValue(store.get(selector));
    });
  }, [store, selector]);

  return value;
}

// 사용
function Counter() {
  const count = useSelector((state) => state.count);
  // count만 변경될 때만 리렌더
}
```

## 🚫 흔한 안티 패턴

실전에서 자주 발생하는 성능 저하 패턴과 해결 방법입니다.

| 패턴                                     | 문제                                     | 대안                                     |
| ---------------------------------------- | ---------------------------------------- | ---------------------------------------- |
| `useEffect`로 파생 상태 동기화           | 불필요한 리렌더·경합 조건 발생           | 렌더 중 계산, 비싸면 `useMemo`           |
| 인라인 객체/함수를 props로 전달          | `React.memo` 무력화                      | `useMemo`/`useCallback`로 참조 안정화    |
| Context에 자주 변하는 큰 객체            | 광범위한 리렌더                          | Context 분리, value를 `useMemo`로 고정   |
| 리스트에 index를 key로 사용              | 재정렬 시 버그·불필요한 리렌더           | 안정적인 고유 ID 사용                    |
| Proxy/DeepFreeze 상태를 직접 전달        | 엔진 최적화 저해                         | 얕은 불변성 유지, 셀렉터 사용            |
| 렌더 중 무거운 동기 연산                 | INP(Interaction to Next Paint) 악화      | `startTransition`·웹 워커·지연 계산      |
| 모든 함수에 `useCallback` 적용           | 불필요한 메모리·복잡도 증가              | 자식이 `memo`이거나 의존성에 넣을 때만   |
| `useState`로 DOM 참조/타이머 ID 저장     | 불필요한 리렌더                          | `useRef` 사용                            |
| 컴포넌트 내부에 컴포넌트 정의            | 매 렌더마다 새 타입 생성 → 전체 리마운트 | 컴포넌트를 외부로 분리                   |
| Context value에 인라인 JSX 엘리먼트 포함 | 매번 새 참조 → 구독자 전체 리렌더        | `useMemo`로 엘리먼트 고정 또는 타입 전달 |
| 여러 `useEffect`를 하나로 합침           | 의존성 복잡화, 불필요한 실행             | 역할별로 분리, 의존성 최소화             |
| `useEffect` 의존성 배열 누락             | Stale closure 버그                       | ESLint 경고 따르기, 의존성 명시          |

## 메모리 누수 방지

React 애플리케이션에서 흔히 발생하는 메모리 누수 패턴과 해결 방법입니다.

### 1. Effect Cleanup 필수

```tsx
// ❌ 메모리 누수: cleanup 없음
useEffect(() => {
  const timer = setInterval(() => {
    console.log("tick");
  }, 1000);
  // 컴포넌트 언마운트 시에도 타이머 계속 실행!
}, []);

// ✅ 올바른 패턴: cleanup 함수 반환
useEffect(() => {
  const timer = setInterval(() => {
    console.log("tick");
  }, 1000);

  return () => {
    clearInterval(timer); // 반드시 정리
  };
}, []);
```

### 2. 이벤트 리스너 정리

```tsx
// ❌ 메모리 누수: 이벤트 리스너 미제거
useEffect(() => {
  const handleResize = () => {
    console.log("resized");
  };
  window.addEventListener("resize", handleResize);
}, []);

// ✅ 올바른 패턴: 리스너 제거
useEffect(() => {
  const handleResize = () => {
    console.log("resized");
  };
  window.addEventListener("resize", handleResize);

  return () => {
    window.removeEventListener("resize", handleResize);
  };
}, []);
```

### 3. 비동기 작업 취소

```tsx
// ❌ 메모리 누수: 언마운트 후에도 setState 실행
useEffect(() => {
  fetchData().then((data) => {
    setData(data); // 컴포넌트가 언마운트되면 경고 발생
  });
}, []);

// ✅ 올바른 패턴: 취소 플래그 사용
useEffect(() => {
  let isMounted = true;

  fetchData().then((data) => {
    if (isMounted) {
      setData(data);
    }
  });

  return () => {
    isMounted = false;
  };
}, []);

// ✅ 더 나은 패턴: AbortController 사용
useEffect(() => {
  const controller = new AbortController();

  fetch("/api/data", { signal: controller.signal })
    .then((res) => res.json())
    .then((data) => setData(data))
    .catch((err) => {
      if (err.name !== "AbortError") {
        console.error(err);
      }
    });

  return () => {
    controller.abort();
  };
}, []);
```

### 4. 디바운스/스로틀 정리

```tsx
// ❌ 메모리 누수: 디바운스 미취소
const handleSearch = useMemo(
  () => debounce((query: string) => search(query), 300),
  []
);

// ✅ 올바른 패턴: cleanup에서 취소
const handleSearch = useMemo(
  () => debounce((query: string) => search(query), 300),
  []
);

useEffect(() => {
  return () => {
    handleSearch.cancel();
  };
}, [handleSearch]);
```

### 5. Subscription/Observable 해제

```tsx
// Redux, RxJS 등의 구독 해제
useEffect(() => {
  const unsubscribe = store.subscribe(() => {
    console.log("state changed");
  });

  return () => {
    unsubscribe();
  };
}, []);

// EventEmitter 정리
useEffect(() => {
  const handler = (data) => console.log(data);
  eventEmitter.on("event", handler);

  return () => {
    eventEmitter.off("event", handler);
  };
}, []);
```

```tsx
// ❌ 위험: dangerouslySetInnerHTML 사용

import DOMPurify from "dompurify";
```

### 3. 안전한 URL 처리

```tsx
// ❌ 위험: 사용자 입력을 그대로 href에 사용
<a href={userInput}>Link</a>

// ✅ 안전: URL 검증
function SafeLink({ href, children }) {
  const isSafe = useMemo(() => {
    try {
      const url = new URL(href);
      return ["http:", "https:"].includes(url.protocol);
    } catch {
      return false;
    }
  }, [href]);

  if (!isSafe) {
    return <span>{children}</span>;
  }

  return <a href={href} rel="noopener noreferrer">{children}</a>;
}
```
